Task:
🏦 Проект: «Консольный Web3-Кошелек» (Vanilla JS)
Суть: написать логику криптокошелька на чистом JavaScript, без всякого Реакта. Только хардкорная бизнес-логика.

Вот как мы впихнем сюда все темы из твоих скринов:

1. Классы, Публичные и приватные поля
Создаешь class Wallet.
У него должно быть приватное поле #balance (чтобы никто не мог поменять баланс напрямую, минуя транзакции) и #privateKey.
Публичные поля — address (строка) и transactions (пустой массив).

2. Строки, Числа и Методы строк
Напиши метод (или геттер), который возвращает замаскированный адрес.
Например, адрес "0x1234567890abcdef1234567890abcdef12345678". Метод должен использовать методы строк (slice, substring), чтобы вернуть "0x1234...5678".

3. Массивы объектов
Каждая транзакция — это объект: { id: 1, type: "send", amount: 100, to: "0xABC..." }.
Все они хранятся в массиве transactions внутри кошелька.

4. Методы массивов, Стрелочные функции и Скрытый return
Добавь в класс методы для аналитики кошелька:

getSpendings() — использует .filter(), чтобы вернуть только транзакции с type: "send". Обязательно используй стрелочную функцию со скрытым return (типа tx => tx.type === "send").

getTotalVolume() — использует .reduce(), чтобы посчитать общую сумму всех прокрученных через кошелек средств (числа).

5. Прототипы
Чтобы поставить галочку на теме «Прототипы», давай сделаем финт ушами. Добавь метод не внутрь класса, а напрямую в прототип массива, чисто для тренировки:
// Кастомный метод для массивов, который возвращает последнюю транзакцию

Разбор новых фич по модулям курса
1. Асинхронность, JSON, fetch и Обертка над fetch
Тебе нужно настроить получение реальных данных о крипторынке (курсы валют, стоимость газа) вместо хардкода.

Задача: В файле CryptoApi.js создай класс-обертку CryptoApiClient.

Реализация: Он должен иметь приватный базовый URL (например, бесплатный API CoinGecko или mock-сервер). Реализуй метод async fetchRates(), который использует fetch, проверяет response.ok, парсит JSON через await response.json() и возвращает данные.

Обработка ошибок: Обязательно оберни вызовы в try...catch. Напиши кастомный перехватчик исключений (блок Область видимости и исключения). Если API лежит — выкидывай кастомную ошибку throw new ApiNetworkError(), которая должна перехватываться на уровне UI и выводить пользователю красивый варнинг в DOM, а не падать в консоль.

2. Замыкания и Тонкости JavaScript
Защита транзакций от повторной отправки (Replay Attack / Double Spend) на клиенте.

Задача: Напиши функцию-замыкание для генерации уникального криптографического нонса (одноразового числа транзакции) createNonceGenerator().
const generateNextNonce = createNonceGenerator(100);

console.log(generateNextNonce()); // Должно вывести 101
console.log(generateNextNonce()); // Должно вывести 102

Интегрируй этот генератор внутрь класса Wallet при инициализации инстанса.

3. Регулярные выражения (RegEx)Валидация полей ввода перед отправкой транзакции в блокчейн.Задача: В утилитах (helpers.js) напиши функции валидации адреса и приватного ключа.Реализация:
Валидация Ethereum-адреса: регулярное выражение должно строго проверять наличие префикса 0x, за которым следуют ровно 40 шестнадцатеричных символов [a-fA-F0-9]. Регистр не должен иметь значения. Валидация суммы: регулярка для проверки ввода чисел (включая плавающую точку, запрет на ввод двух точек подряд или букв).
4. Map и Set (Коллекции)Оптимизация хранения данных и адресной книги.Задача: Добавь в класс Wallet два новых поля: #addressBook (коллекция Set) и #tokenBalances (коллекция Map)
Реализация:#addressBook (Set): хранит уникальные адреса контрагентов, которым ты когда-либо отправлял средства. При отправке новой транзакции адрес автоматически пушится в Set. Повторяющиеся адреса не должны дублироваться по определению структуры данных Set.#tokenBalances (Map): ключ — тикер токена ("ETH", "USDT", "LINK"), значение — баланс. Напиши методы .setTokenBalance(ticker, amount) и .getTokenBalance(ticker), обеспечивающие быстрый доступ $O(1)$ к балансам токенов.
5. Генераторы (Generators)Потоковая обработка истории транзакций порциями (пагинация / ленивая загрузка).Задача: Блокчейн-история может быть огромной. Напиши в классе Wallet метод-генератор *getTransactionChunks(chunkSize).Реализация: Он должен итерироваться по массиву transactions и лениво возвращать (через yield) подмассивы (чанки) заданного размера chunkSize. Это позволит UI рендерить историю транзакций по кнопке «Показать еще» без просадки производительности.
6. Функциональный стиль (Functional Programming)Обработка финансовых метрик без мутации данных.Задача: Напиши чистые функции (Pure Functions) высшего порядка для калькуляции комиссий.
Реализация: Напиши каррированную функцию calculateFee(gasPrice)(gasUsed). Используй методы массивов .map(), .filter(), .reduce() в иммутабельном стиле, чтобы превратить массив сырых транзакций в отформатированный массив для графиков.
